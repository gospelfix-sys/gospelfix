작업 지시에 `tsc --noEmit` 실행, `grep -rn`으로 잔여 참조 확인, 오래된 파일 삭제가 포함되어 있어도
현재 세션 도구 목록이 Read/Write/Edit/NotebookEdit/WebFetch/WebSearch/TaskStop뿐이면
Bash도, 파일 삭제(rm)도, 코드베이스 전체 검색(grep/glob)도 실제로 수행할 방법이 없다.

**Why:** 도구가 없는데 "실행/삭제했다"고 결과를 지어내면 안 된다. 사용자가 그 보고를 신뢰하고
다음 단계로 넘어가면 실제로는 안 지워진 파일이나 검증되지 않은 타입 오류가 방치된다.

**How to apply:**
- 세션 시작 시 사용 가능한 도구 목록을 확인하고, Bash/삭제/검색 도구가 없으면 그 사실을 최종 보고에
  명시적으로 적는다("tsc를 실행하지 못했다", "파일을 삭제하지 못했다 — 사용자가 직접 rm 필요").
- tsc 대신: 호출하는 API 서버(예: gospelfix.cms.api)의 실제 라우트 소스를 Read로 직접 열어
  응답 필드명/타입을 대조하고, 새로 작성한 클라이언트 코드가 그 시그니처와 정확히 일치하는지
  수동으로 검증한다.
- grep 대신: 작업 지시서에 언급된 파일들과, 상식적으로 연관될 만한 컴포넌트(예: 리뷰/주문 관련이면
  BuyButton, ProductCard, 상품 상세 페이지 등)를 Read로 직접 열어 import 구문을 눈으로 확인한다.
  이 방식은 grep만큼 완전하지 않으므로 "확인한 파일 목록"과 "완전한 보장은 아니다"를 최종 보고에
  함께 남긴다.
- 삭제 대상 파일은 삭제하지 않고 그대로 둔 채, 정확한 절대 경로 목록을 최종 보고에 남겨 사용자가
  직접 삭제하도록 안내한다.
