[[project_quote_chat_modal_feature]] 작업 중, 경쟁사("조은마케팅 간편견적") 스크린샷의
결과 화면에는 두 가지가 있었다: (1) 수집한 답변을 "서비스형 · 1페이지"처럼 그 서비스만의
축약된 커스텀 카테고리 라벨로 요약해서 보여주는 UI, (2) 개인정보 수집·이용 동의
아코디언에 "신청일로부터 1년 후 자동 삭제"라는 구체적 보유기간 문구. 사용자에게
AskUserQuestion으로 확인한 결과, 둘 다 그대로 베끼지 않기로 결정했다:

- (1) 요약 박스는 커스텀 라벨링 대신 **지금 수집된 답변 원문을 그대로 나열**하는 방식으로
  구현 — 그 라벨링 체계 자체가 경쟁사 서비스의 산출물이라 가져다 쓸 근거가 없었음.
- (2) 보유기간 문구는 실제 `PrivacyContent.tsx`를 먼저 읽어 확인한 결과, 이 프로젝트의
  개인정보처리방침에는 회원 정보(탈퇴 시까지)/구매 기록(전자상거래법 5년)/접속 로그(3개월)
  조항만 있고 "리드 데이터 1년 자동 삭제" 조항이 아예 없었다 — 그래서 그 숫자를 그대로
  베끼면 실제 방침과 다른 허위 법적 고지가 될 뻔했다. 대신 숫자를 명시하지 않고
  수집 목적/항목/동의 거부 시 결과만 정확히 적은 뒤, 실제 `LegalDialogTrigger
  type="privacy"` 링크로 전체 방침을 보게 했다.

**Why:** 레퍼런스 스크린샷은 "이런 느낌의 UX를 만들어달라"는 디자인 의도 전달 수단이지,
그 안의 구체적 텍스트·분류 체계까지 그대로 복제해도 된다는 뜻이 아니다. 특히 법적 고지
문구는 실제 이 프로젝트의 정책 문서와 대조하지 않고 베끼면 허위 정보가 될 위험이 있고,
커스텀 라벨링 체계는 그 경쟁사가 만든 지적 산출물이라 재사용 근거가 약하다.

**How to apply:** 앞으로도 경쟁사/레퍼런스 스크린샷을 보고 UI를 만들 때는 (a) 레이아웃·
흐름·톤은 참고하되 (b) 그 서비스만의 고유한 분류·네이밍 체계는 이 프로젝트의 실제 데이터
구조로 치환하고 (c) 법적/정책 관련 문구가 있으면 반드시 이 프로젝트의 실제 정책 파일
(`components/legal/*.tsx`)과 대조해서 사실과 다르면 쓰지 않는다. 애매하면 베끼지 말고
AskUserQuestion으로 먼저 확인할 것.
