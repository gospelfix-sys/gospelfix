공용(shared)·공통(common)으로 여러 곳에서 쓰이는 컴포넌트나 스타일을 조정해야 할 때는, 각
호출부(사용하는 쪽)에서 매번 값을 개별적으로 덮어쓰는 방식이 아니라 **그 요소가 정의된 공용
파일 자체를 고쳐서 모든 사용처에 자동으로 반영**되도록 한다. 특정 컴포넌트에 국한되지 않는
프로젝트 전반의 일반 원칙이다 — `components/ui/*`의 UI 프리미티브, 공용 훅, 공용 유틸 함수,
`tailwind.config.ts`의 공용 토큰 모두에 동일하게 적용한다. 정식 규칙 문서는
`.claude/rules/shared-component-changes.md` 참고.

**Why:** 개별 호출부에서 매번 반복 지정하는 방식은, 다음에 같은 컴포넌트를 새로 쓰거나 만들
때 이 규칙을 깜빡하면(사람이든 에이전트든) 똑같은 버그가 재발한다. 실제로
`components/ui/dialog.tsx`의 `DialogContent`에서 이 문제가 한 세션 안에서 두 번 반복됐다:
모바일 좌우 여백이 `max-w-[calc(100%-2rem)]`라는 "max-width" 계열 유틸리티로 구현돼
있었는데, 두 호출부(`OptionToggle.tsx`, `ProductOptionsSection.tsx`)가 데스크톱 너비를
키우려고 접두사 없는 `max-w-lg`/`max-w-md`를 덮어쓰면서 tailwind-merge가 이를 "같은
유틸리티 그룹"으로 보고 모바일 여백까지 함께 지워버렸다. 호출부마다
`max-w-[calc(100%-2rem)] sm:max-w-*`를 다시 써주는 임시방편도 가능했지만, 세 번째
호출부가 생기면 또 깨질 뿐이다. 근본 수정은 `dialog.tsx`의 `DialogContent` 자체를 재설계해
모바일 여백(`inset-x-4`, position 속성)과 데스크톱 너비(`sm:max-w-*`, max-width 속성)를
애초에 서로 다른 CSS 속성으로 분리하는 것이었다 — 이러면 어떤 호출부가 접두사 없이
`max-w-*`를 덮어써도 모바일 여백은 절대 깨지지 않는다.

**How to apply:** 공용 정의(`components/ui/*.tsx`, 공용 훅, 공용 유틸)를 다룰 때 "이 변경을
쓰는 곳마다 반복해야 하는가?"를 먼저 자문한다. 반복해야 한다면 그 자체가 신호다 — 공용 정의
파일을 고쳐서 한 곳에서 전체 반영되도록 재설계할 것. 개별 호출부 수정은 그 호출부만 예외적인
값(예: 이 다이얼로그만 유독 넓어야 함)이 필요할 때만 쓰고, 모든 사용처에 공통으로 보장돼야
하는 동작(예: 모바일 여백)은 반드시 공용 파일 레벨에서 서로 다른 관심사로 분리해 보장한다.
