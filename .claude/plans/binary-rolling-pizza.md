# 비즈니스 모델 v2(양면 마켓플레이스) 반영 — ROADMAP.md 신설 + 메모리 갱신

## Context

`gospelfix-business-model.md`가 이전 대화 이후 크게 갱신됐다(191줄 → 266줄). 이전
버전은 "GospelFix가 직접 만들어 파는 버티컬 AI 홈페이지 SaaS"였는데, 새 버전은
**양면 마켓플레이스**로 확장됐다: 구매자(소상공인)가 AI 홈페이지·템플릿을 사고,
판매자(AI 빌더 = 개발자·디자이너·1인창업자·프리랜서)가 템플릿·컴포넌트·프롬프트
파일을 등록해 팔며, GospelFix는 검수·승인·정산을 담당하고 수수료 30%를 가져간다
(판매자 70%/GospelFix 30%). 판매자 마이페이지, Supabase `role` 컬럼(buyer/seller/
admin), Toss 정산 API, 리뷰·평점 테이블 등 구체적 기술 구현 사항도 명시됐고,
"전체 성장 로드맵"으로 Phase 1(지금~1개월)/Phase 2(1~3개월)/Phase 3(3~6개월)가
새로 정의됐다.

단, Phase 3(외부 판매자 베타 초대·마이페이지 오픈·수수료 수익 시작)는 3~6개월
후로 명시되어 있고, 지금(Phase 1)은 여전히 "GospelFix 자체 상품 10개 + AI 챗봇
개발 + 콘텐츠 10개"에 집중하는 단계다. 사용자도 확인 질문에서 "판매자 입점" 같은
티저 문구를 지금 페이지에 넣지 않기로 확정했다(실제 입점 기능이 없는 상태에서
문구만 노출하면 과장광고가 됨).

**따라서 이번 작업의 실질 범위는:**
1. `/`, `/about`, `/mall`의 구매자 대상 설명 카피는 **이미 이전 대화에서 새 방향
   (업종별 AI 홈페이지 + AI 챗봇 24시간 자동응대 + 유지보수 MRR)으로 전면
   반영·검증(lint+build) 완료된 상태**이고, 이번 문서 갱신분(판매자 마켓플레이스)은
   Phase 3라 지금 페이지 카피에 추가 반영하지 않는다 → **이 세 페이지는 추가 수정
   없음**.
2. 사용자가 명시적으로 요청한 "기능 수정은 하지 말고 plan만 세워달라"에 따라,
   AI 챗봇 개발·유지보수 구독 결제·회원 전환 퍼널 자동화·판매자 마켓플레이스라는
   **미구현 기능들을 실제 코드로 만들지 않고, 저장소에 `ROADMAP.md`로 문서화**한다.
3. `.claude/memory/project_business_model_vertical_ai_pivot.md`를 새 비즈니스
   모델 v2 내용으로 전면 갱신하고, 향후 기능 요청을 이 로드맵의 Phase 구분과
   대조해 판단하도록 "How to apply" 기준을 업데이트한다.

## 1. `ROADMAP.md` 신규 생성 (저장소 루트)

`development-planner` 에이전트가 다루는 것과 같은 성격의 산출물이라 프로젝트
관례상 루트에 둔다. 구조:

- **지금 상태(완료됨)**: `/`·`/about`·`/mall` 카피 반영 완료 명시, 실제 상품
  카테고리(`landing`/`dashboard`/`ecommerce`/`corporate`)가 이미 문서의 카테고리
  표와 일치한다는 점 기록
- **Phase 1 (지금~1개월)**: 자체 상품 10개(우선순위: 뷰티·헬스·필라테스 →
  이사·청소 → 요식업·카페 → 병원·한의원·치과 → 학원·교육) + AI 챗봇 3주 개발
  일정(1주차 Claude API 연동+기본 UI / 2주차 FAQ+견적자동화+카카오알림(선택) /
  3주차 프롬프트 튜닝+템플릿 삽입+테스트) + 콘텐츠 10개
- **Phase 2 (1~3개월)**: 메타 광고 시작 조건(상품10+콘텐츠10+후기3 달성 후),
  후기 10개, 유지보수 MRR 100만원 목표 → **월정액 자동결제/구독관리 기능이
  아직 없다는 점**(현재 계좌이체 1회성 결제만 존재, 기존 메모리
  `project_toss_payments_history.md` 참고)을 필요조건으로 명시
- **Phase 3 (3~6개월)**: 외부 AI 빌더 판매자 베타(지인 3명) + 판매자
  마이페이지(상품 CRUD/판매현황/정산내역/프로필) + 수수료 수익(70/30) 시작.
  기술 구현 체크리스트: Supabase `profiles.role`(buyer/seller/admin) 컬럼,
  상품 등록 권한을 `role=seller`로 제한, Toss 정산 API, 리뷰·평점 테이블,
  판매자 대시보드 UI
- **회원 전환 퍼널 자동화** (Phase 구분 없이 조기 착수 가능한 별도 트랙):
  회원가입 시 FREE 템플릿 즉시 지급 + 첫구매 20% 쿠폰 자동 발급(30일), 기존
  `lib/coupon.ts`/`app/api/coupons` 재사용 가능성 확인 필요. 카카오 챗봇 연동·
  AI 자동응답·월간 리포트는 전환비용(switching cost) 장치로 명시
- **보류 결정**: 판매자 마켓플레이스 티저 문구는 실제 기능 출시 전까지 페이지에
  넣지 않는다(2026-08-14 사용자 확인 근거 기록)
- **참고 링크**: 원본 문서 경로, 정렬 기준 메모리 파일 경로

## 2. `.claude/memory/project_business_model_vertical_ai_pivot.md` 전면 갱신

기존 파일(단일 판매자 버티컬 SaaS 관점)을 새 문서 기준으로 다시 쓴다. 파일명·
frontmatter의 `name`/`type: project`는 유지(같은 주제의 최신화이므로 새 파일을
만들지 않음). 갱신 내용:

- 플랫폼 구조: 구매자(소상공인)/판매자(AI 빌더)/운영자(GospelFix) 3자 구조,
  "소상공인이 낸다 → AI 빌더가 만든다 → GospelFix가 연결하고 수수료를 받는다"
- 구매자 타겟(기존과 동일: 뷰티/이사/카페/병원/학원, 1~5인, 아임웹도 어려움)
- 판매자 타겟: 개발자·디자이너·1인창업자·프리랜서, "트래픽 없어서 못 파는" 니즈
- 경쟁 포지셔닝에 크몽(용역 중계, 파일판매 아님) 추가, GospelFix는 "AI 탑재
  템플릿+배포+마켓플레이스"로 재정의
- 가격구조 + 판매자 수익구조(70/30) 병기
- 판매자 시스템: 권한구조(buyer/seller/admin), 수동 승인제, 마이페이지 기능,
  기술 구현 메모(Supabase role 컬럼 등)
- 성장 로드맵 Phase 1/2/3 요약 + 실행 우선순위 6개 항목(6번 "AI 빌더 판매자
  기능 오픈"이 새로 추가됨)
- **How to apply** 갱신: 기존 5축 정렬 기준은 유지하되, 새 축 추가 — "⑥ 이
  기능이 Phase 1(자체 상품/챗봇) 범위인가, 아니면 Phase 3(판매자 마켓플레이스)
  범위인가?" Phase 3 성격의 기능 요청이 지금 들어오면 "아직 이르다, ROADMAP.md
  Phase 3 참고"라고 알리고, Phase 1과 무관한 기능은 기존과 같이 "비즈니스
  방향성과 맞지 않는다"고 지적할 것
- `ROADMAP.md`를 정식 참고 링크로 추가

`.claude/memory/MEMORY.md`의 기존 포인터 한 줄도 이 갱신 내용에 맞게 다시 씀
(양면 마켓플레이스로 확장됐다는 것, ROADMAP.md 신설 사실 반영).
