# gospelfix PRD

> **한 줄 요약**: 홈페이지/쇼핑몰 템플릿을 판매하는 마켓플레이스 구매자용 사이트. 인증·상품·주문 등 모든 데이터는 자체 DB 없이 `gospelfix.cms.api`를 BFF로 호출해 처리한다
> **작성일**: 2026-04-22 | **최종 갱신**: 2026-07-27 | **상태**: 핵심 구매 흐름(마켓·상세·수동 계좌이체 결제·마이페이지) 운영 중, 장바구니·소셜 로그인·PG 연동은 미구현

---

## 1. 이 서비스는 무엇인가

`gospelfix`는 홈페이지/쇼핑몰/디자인 템플릿을 판매하는 마켓플레이스의 **구매자용 공개 사이트**다 (포트 3000). 이 저장소는 **자체 DB를 갖지 않는 순수 BFF(Backend-For-Frontend)** 구조로, 인증·상품·주문·리뷰 등 모든 데이터 작업은 서버 사이드에서 `gospelfix.cms.api`(별도 레포, 포트 3001)를 `X-API-Key`로 호출해 처리한다. 브라우저는 이 앱의 `/api/*` 라우트만 호출하고, `gospelfix.cms.api`를 직접 호출하지 않는다.

**성공 지표**

- 방문자가 회원가입 → 템플릿 탐색 → 구매 → 계좌이체 → 다운로드까지 이탈 없이 완주
- 관리자(별도 CMS)가 승인한 콘텐츠(상품/포트폴리오/블로그)가 이 사이트에 실시간으로 반영됨

---

## 2. 사용자

**주요 사용자**: 템플릿을 찾고 구매하는 일반 방문자/구매자. 이 저장소에는 관리자용 화면이 없다(관리는 `gospelfix.cms.api`에서 별도로 함).

**핵심 사용 시나리오**

1. 방문자가 홈에서 포트폴리오를 둘러보고 `/mall`에서 카테고리별 템플릿 탐색 → `/detail/[slug]`에서 상세 확인
2. 구매 버튼 클릭 → 비로그인 시 팝업으로 회원가입/로그인 → 구매 진행
3. 무료 상품은 즉시 완료, 유료 상품은 계좌이체 안내(QR/계좌번호) → "입금했어요" 클릭 → 관리자 수동 확인 대기 → `/dashboard`에서 다운로드
4. 커스텀 제작이 필요하면 `/quote`에서 5단계 견적 마법사로 요청서 제출

---

## 3. 핵심 기능

### 3.1 회원가입/로그인 — 완료 (팝업 모달)

별도 `/login`, `/register` 페이지가 아니라 **어느 화면에서든 열리는 팝업(Dialog) 모달**로 전환됨. `/login`, `/register`는 이전 링크 호환을 위한 리다이렉트 셔임(shim)으로만 남아있다 (`openAuthModal()` 호출 후 `/`로 이동).

- **로그인**: 이메일/비밀번호 → `POST /api/auth/login` → 세션 쿠키 설정
- **회원가입**: 이메일 인증(인증번호 발송 `sendEmailCode` → 확인 `verifyEmailCode`, 1회용 토큰을 `signUp()`에 포함, 서버 재검증) + 비밀번호 + 필수 약관 동의 3종(이용약관·개인정보 수집·이용·만 14세 이상, 클라이언트 검증)만 받는다. 유출 피해를 줄이기 위한 최소 수집 정책으로, 이름·휴대폰은 가입 시 받지 않고 실제로 필요한 기능이 생길 때 그 시점에 수집한다. 카카오 로그인은 `account_email`만 요청한다
- **비밀번호 확인 필드** 있음(제출 전 일치 검증, 이중 가드)
- **소셜 로그인**: UI 진입점은 있으나 `signInWithOAuth()`가 항상 "현재 준비 중입니다" 에러를 던지는 **하드 스텁** — 미구현 상태
- 전역 상태: Recoil `authModalAtom`(어느 페이지에서든 모달 열기/닫기), `useAuth()` 훅으로 전체 인증 로직 캡슐화

### 3.2 상품 탐색 & 구매 — 완료 (수동 계좌이체, PG 미연동)

- `/mall`: 카테고리 필터 + 템플릿 그리드
- `/detail/[slug]`: 디바이스 미리보기 프레임, 구매 옵션 패널(HTML/PSD/Figma 소스, 플랫폼별 옵션), 리뷰 섹션
- **구매 흐름**: 구매 버튼 → `POST /api/orders/create`(가격 서버 재검증) → 무료 상품은 즉시 완료 처리, 유료 상품은 **결제 모달**(정적 QR 이미지 + 계좌번호 안내, 실제 PG 연동 없음) → 구매자가 계좌이체 후 "입금했어요" 클릭 → `POST /api/orders/notify-payment` → **관리자가 CMS에서 수동으로 입금 확인**해야 다운로드 가능해짐 (웹훅/자동 확인 없음)
- 이미 구매한 상품 재구매 시 409로 차단
- **장바구니 미구현**: 담기 버튼이 "장바구니 기능은 준비 중입니다" 토스트만 띄움 — 단건 즉시구매만 가능

### 3.3 마이페이지 — 완료 (단일 페이지, 최소 기능)

`/dashboard` 한 페이지만 존재: 이메일/역할/가입일 카드 + 구매 내역 목록 + 다운로드 링크. 프로필 수정, 비밀번호 변경, 주문 상세/영수증, 리뷰 관리 페이지는 없음. 다운로드는 `gospelfix.cms.api`가 서명한 URL로 리다이렉트되며, 파일이 아직 업로드 안 된 상품은 "파일 준비 중입니다" 안내로 대체됨

### 3.4 커스텀 견적 마법사 — 완료

`/quote`: 카테고리 → 항목 선택 → 일정 → 스타일 → 연락처, 5단계 마법사. 상태는 Recoil `quoteWizardAtom`으로 관리되며 `sessionStorage`에 저장돼 새로고침해도 유지됨. 제출 시 Server Action(`submitQuoteAction`)이 IP/UA/리퍼러를 붙여 `/api/quotes`로 전송

### 3.5 블로그 — 완료

`/blog`, `/blog/[slug]` — `gospelfix.cms.api`의 블로그(뉴스) 콘텐츠를 Lexical 에디터 HTML로 렌더링(DOMPurify로 새니타이즈)

### 3.6 리뷰 — 완료

상품 상세 페이지에서 조회 공개, 작성은 로그인 + **실제 구매 검증** 필요(미구매 시 403)

## 4. 기술 스택

| 항목              | 사용                                                                                                       |
| ----------------- | ---------------------------------------------------------------------------------------------------------- |
| 프레임워크        | Next.js 14 (App Router)                                                                                    |
| 스타일            | Tailwind CSS **v3.4** + shadcn/ui (`base-nova` 스타일)                                                     |
| UI 프리미티브     | `@base-ui/react`로 전환 중 — **아직 완전 이전 아님**, `@radix-ui/react-label`/`react-slot`도 일부 남아있음 |
| 상태 관리         | Recoil (`authAtom`, `userAtom`, `uiAtom`, `quoteAtom`)                                                     |
| HTTP (서버)       | `cmsApiFetch()` — `gospelfix.cms.api` 전용 axios 래퍼, `X-API-Key` + 선택적 `Authorization: Bearer`        |
| HTTP (클라이언트) | axios 인스턴스, 같은 오리진 `/api/*`만 호출, 401 시 `/login`으로 리다이렉트                                |
| 폼                | `react-hook-form`                                                                                          |
| 캐러셀            | Swiper                                                                                                     |
| 아이콘            | lucide-react                                                                                               |
| 폰트              | Pretendard(국문), DM Sans(영문), Playfair Display(포인트 세리프)                                           |
| 개발 포트         | 3000                                                                                                       |
| 배포              | Vercel (Git 연동 자동배포)                                                                                 |

**아키텍처 원칙**

- 이 저장소는 **자체 Supabase/DB 접근이 전혀 없다** — 모든 데이터는 `gospelfix.cms.api`를 통해서만 오간다
- Server Component는 이 앱 자신의 `/api/*`를 `serverFetch()`로 호출하고, Route Handler(`/api/*`)만 `cmsApiFetch()`로 `gospelfix.cms.api`를 호출한다 — 브라우저가 `gospelfix.cms.api`를 직접 볼 일이 없음
- 브랜드 컬러: `--gf-orange #ff5500`(포인트), `--gf-bg #f7f5f0`(배경) — shadcn CSS 변수에 매핑

**환경변수**

```env
CMS_API_BASE_URL=          # 예: http://localhost:3001 또는 gospelfix.cms.api 배포 URL
CMS_API_KEY=                # gospelfix.cms.api의 INTERNAL_API_KEY와 동일한 값 (서버 전용)

NEXT_PUBLIC_PAYMENT_BANK=   # 계좌이체 안내용, 클라이언트 노출 무방
NEXT_PUBLIC_PAYMENT_ACCOUNT=
NEXT_PUBLIC_PAYMENT_HOLDER=
```

> `CMS_API_KEY`는 서버 전용이라 `NEXT_PUBLIC_` 접두사가 없다 — 클라이언트 번들에 노출되면 안 됨. Vercel 배포 시 **로컬 `.env.local`과 별개로 Vercel 대시보드에도 반드시 등록**해야 한다(둘은 자동 동기화되지 않음).

## 5. 리스크 & 결정 필요 사항

- **장바구니 미구현**: 단건 즉시구매만 가능. 여러 템플릿을 한 번에 사고 싶은 사용자를 못 받는 구조
- **소셜 로그인 하드 스텁**: UI가 있어 보이지만 클릭하면 항상 에러 — 노출된 상태라면 사용자 혼란 유발 가능, 버튼을 숨기거나 실제 구현 필요
- **결제가 완전 수동**: PG 연동 없이 계좌이체 + 관리자 수동 확인 — 주문량이 늘면 확인 지연이 곧 구매 경험 저하로 이어짐. 자동 입금 확인(가상계좌 등) 도입 검토 필요
- **환불/취소 플로우 없음**: 앱 어디에도 취소/환불 관련 화면이 없음
- **`PurchaseOptionsPanel`의 공급원가가 임시 목업**: 코드에 `TODO: cms.api supply_price 필드 추가 전 임시 목업 (공급원가 = 판매가의 2배)` 주석 — 실제 필드 추가 전까지 원가 표시가 부정확할 수 있음
- **마이페이지가 최소 기능**: 프로필 수정, 비밀번호 변경, 주문 상세, 리뷰 관리 화면이 전혀 없음
- **`@base-ui/react` 마이그레이션 미완료**: 일부 컴포넌트가 여전히 `@radix-ui`(`Label`, `Slot`) 사용 — 완전 전환 여부 결정 필요
- **콘텐츠가 아직 채워지는 중**: `/mall` 특정 카테고리, 홈 포트폴리오 섹션에 "준비 중입니다" placeholder가 남아있는 카테고리 존재
