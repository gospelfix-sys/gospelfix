# gospelfix PRD

> **한 줄 요약**: 브랜딩 디자인 소재(CI 로고·목업·홈페이지·대시보드·이커머스 템플릿·광고 소재 PSD/AI)를 판매하는 마켓플레이스의 사용자 앱. 자체 DB 없이 `gospelfix.cms.api`를 BFF로 호출해 모든 데이터를 처리한다
> **작성일**: 2026-04-22 | **최종 갱신**: 2026-10-27 | **상태**: 마켓·상세·장바구니·계좌이체 결제·마이페이지·카카오 로그인 운영 중, PG 연동과 환불 흐름은 없음

---

## 1. 이 서비스는 무엇인가

`gospelfix`는 브랜딩에 들어가는 디자인 소재를 판매하는 마켓플레이스의 **사용자 앱**이다(포트 3000). 인증·상품·주문·리뷰 등 모든 데이터는 서버 사이드에서 `gospelfix.cms.api`(별도 저장소, 포트 3001)를 `X-API-Key`로 호출해 처리한다. 브라우저는 이 앱의 `/api/*`만 호출하고 cms.api를 직접 호출하지 않는다. 관리자 화면은 이 저장소에 없다.

**성공 지표**

- 방문자가 회원가입 → 소재 탐색 → 구매 → 계좌이체 → 다운로드까지 이탈 없이 완주
- cms.api에서 승인한 콘텐츠(상품·포트폴리오·블로그)가 코드 변경 없이 이 사이트에 반영

---

## 2. 사용자

- **구매자**: 소재를 찾아 구매하고 내려받는 방문자
- **판매자**: 마이페이지에서 판매자 전환을 신청하고 승인되면 작품 업로드 에디터(`/upload`)로 소재를 등록한다 (승인은 cms.api의 관리자가 처리)

**핵심 시나리오**

1. 홈(`/`)에서 소재를 둘러보고 카드를 열면 상세 모달(`/detail/[slug]`), 직접 진입하면 풀 페이지
2. 구매 또는 장바구니 담기 → 비로그인이면 로그인 모달 → 구매 진행
3. 무료 상품은 즉시 완료, 유료 상품은 계좌이체 안내 → "입금했어요" → 관리자 수동 확인 → 마이페이지에서 다운로드

---

## 3. 핵심 기능

### 3.1 회원가입/로그인 — 완료 (모달)

`/login`, `/register`는 페이지가 아니라 `openAuthModal()`을 열고 `/`로 이동한다. `?next=`는 `sanitizeInternalPath`로 검증한다.

- **이메일 가입**: 이메일 인증 코드 → 비밀번호 → 필수 약관 3종. 유출 피해를 줄이려고 이름·휴대폰은 가입 시 받지 않고 필요한 기능이 생길 때 수집한다
- **카카오 로그인**: `/api/auth/kakao` → 콜백. scope는 `account_email`만 요청한다
- 세션은 httpOnly 쿠키(`gf_at`, `gf_rt`, `gf_exp`)에 저장하고 middleware가 만료 임박 시 갱신한다. 보호 경로는 `/mypage`

### 3.2 소재 탐색 & 구매 — 완료 (계좌이체, PG 미연동)

- 홈 `/`: 카테고리별 소재 카드 그리드. 상세는 `@modal` 병렬 라우트로 모달 → 풀 페이지 이중 구성
- 상세: 구매 옵션 패널(라이선스·옵션별 가격), 코드 미리보기, 좋아요·공유, 리뷰, 할인 카운트다운
- **장바구니**: 담기 → 일괄 결제(`orders/create-batch`) 지원
- **쿠폰·추천인**: 쿠폰 조회, 추천인 코드와 배너(`referral-banners`)
- **결제 흐름**: 주문 생성(서버가 가격 재검증) → 무료는 즉시 완료, 유료는 계좌이체 안내 모달 → "입금했어요" → `notify-payment`는 **신고만** 하며 관리자가 입금을 확인해야 다운로드 가능 (웹훅·자동 확인 없음)
- 이미 구매한 상품 재구매는 409로 차단

### 3.3 마이페이지 — 완료

`/mypage`(프로필) · `orders`(주문 내역, 입금 대기 포함) · `products`(내 작품) · `reviews`(내 리뷰) · `settings`(계정 설정: 비밀번호 변경, 판매자 전환 신청, 회원탈퇴)

### 3.4 블로그 — 완료

`/blog`, `/blog/[slug]` — cms.api의 소식 콘텐츠를 HTML로 렌더링한다(`sanitize-html`로 정화). 목록에서는 다크 테마 모달로, 직접 진입하면 풀 페이지로 열린다.

### 3.5 리뷰 — 완료

상세에서 조회는 공개, 작성은 로그인 + 실제 구매 검증(미구매 시 403).

### 3.6 준비 중인 페이지

`/free-resources`(무료 리소스), `/creator`(크리에이터), `/guide`(이용가이드)는 "콘텐츠를 준비 중입니다" 자리표시 상태다.

## 4. 기술 스택

| 항목 | 사용 |
| ---- | ---- |
| 프레임워크 | Next.js 14 (App Router), React 18 |
| 스타일 | Tailwind CSS **v3.4** + shadcn/ui (`base-nova`, `@base-ui/react`) |
| 모션 | `motion/react` (새 CSS 애니메이션 금지) |
| 상태 관리 | Recoil |
| HTTP | 서버: `cmsApiFetch()`(Route Handler 전용) / 브라우저: `axiosInstance`(`/api/*`만) |
| 에디터 | Tiptap (작품 업로드) |
| 캐러셀 | Swiper |
| 분석 | PostHog (쿠키 동의 후에만 초기화) |
| 배포 | Vercel (Git 연동 자동 배포) |

**아키텍처 원칙**

- 이 저장소는 Supabase/DB에 직접 접근하지 않는다. 모든 데이터는 cms.api를 통한다
- Server Component는 `serverFetch()`로 자기 앱의 `/api/*`를 호출하고, Route Handler만 `cmsApiFetch()`로 cms.api를 호출한다
- 환경변수와 상세 구조는 [`CLAUDE.md`](../CLAUDE.md)와 [`llms.txt`](../llms.txt) 참고. `CMS_API_KEY`는 서버 전용이며 환경변수를 바꾸면 Vercel 재배포가 필요하다

## 5. 리스크 & 결정 필요 사항

- **결제가 완전 수동**: PG 없이 계좌이체 + 관리자 수동 확인이라 주문량이 늘면 확인 지연이 곧 구매 경험 저하로 이어진다. 가상계좌 등 자동 입금 확인 도입 검토 필요
- **환불/취소 흐름 없음**: 환불 규정 문구는 있지만 취소·환불을 처리하는 화면과 API가 없다
- **자리표시 페이지**: `/free-resources`, `/creator`, `/guide`가 비어 있다
- **사이트 메타데이터**: `layout.tsx`의 기본 title/OG 문구가 "AI 탑재 웹 템플릿 마켓" 기준이라 현재 정체성(브랜딩 디자인 소재 마켓)과 어긋난다
- **상품 카테고리**: 로고·목업·광고 소재를 따로 나누는 분류가 cms.api와 `FALLBACK_PRODUCT_CATEGORIES`에 아직 없고, PSD/AI 같은 파일 형식 표기용 필드도 없다
- **브랜드명 혼재**: 일부 페이지(`/introduce`, `/creator`, `/free-resources`, `/upload`)는 title에 "모다(MODA)"를, `/about`·`/layer`는 AI 에이전시 시절 문구를 쓴다
